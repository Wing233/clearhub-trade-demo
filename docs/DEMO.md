# 8 分钟演示脚本

## 准备

```bash
cp .env.example .env
docker compose up -d --build
docker compose ps          # 等待 mysql / trade-core / web 均为 healthy
```

浏览器打开 `http://<服务器IP>:8088`，默认账户为「演示用户」（`firmId=2`）。

## 场景 1：看盘（30 秒）

1. 左侧「市场」显示两个商品，价格每 3 秒更新；下方「撮合引擎」卡显示累计委托/成交、未完成委托与撮合规则。
2. 中间「盘口」有 3 档买卖报价，红色为买、绿色为卖；头部显示买一/卖一/价差。
3. 「最近成交」显示做市商、模拟交易员与演示用户的成交，带买/卖方向；「行情走势」为 1 分钟 K 线 + 成交量 + MA5/MA10，首次打开时不足部分用模拟历史补齐。
4. 右侧「市场信息」显示今开/最高/最低、成交量额、买卖盘深度和深度图。
5. 顶部 LIVE 徽标、市场脉搏显示总成交额/量、涨跌家数、行情源与系统时间。
6. 顶部显示当前账户的可用资金、冻结资金、余额。

讲解点：
- 盘口来自内存撮合引擎的快照，不是数据库聚合。
- 做市商每 3 秒围绕参考价双边报价，模拟交易员每 2.5 秒穿越盘口成交，保证演示有流动性和连续 K 线。
- K 线由真实成交按分钟聚合；「含模拟历史」标记表示补了演示用的历史形态。

## 场景 2：买入并成交（1 分钟）

1. 右侧下单面板默认「买入」，价格自动填卖一价。
2. 数量填 `10`（或点 25%）。
3. 点击「买入 示例商品 A」。
4. 观察：
   - 顶部「可用资金」减少，持仓增加；
   - 「我的委托」出现一条「全部成交」；
   - 「我的成交」出现成交记录，成交价是**卖一价**（被动方价格）；
   - 「资金流水」出现「买入成交」扣款。

讲解点：
- 成交价取被动方价格，买方出价高于卖一不会按买方价成交。
- 手续费按成交额 0.05% 双向收取。
- 资金、持仓、成交在同一事务内完成。

## 场景 3：挂单与撤单（1 分钟）

1. 把价格改成明显低于买一的价格（例如 `95.00`），数量 `10`。
2. 点击买入，委托状态为「待成交」。
3. 顶部「冻结资金」增加。
4. 在「我的委托」点击「撤单」。
5. 冻结资金归零，委托状态变为「已撤单」。

讲解点：
- 下单先冻结，成交才扣款，撤单释放剩余冻结。
- 撤单与撮合在同一队列串行，避免“撤单和成交并发”导致超卖。

## 场景 4：卖出（1 分钟）

1. 切换到「卖出」，价格自动填买一价。
2. 数量填 `5`，点击卖出。
3. 持仓减少、可用资金增加；「我的成交」出现卖出记录。
4. 若数量超过可用持仓，会返回「可用持仓不足」。

讲解点：
- 现货模型：卖出必须有可用持仓，不支持卖空。
- 卖出成交额扣除手续费后入账。

## 场景 5：多账户隔离（30 秒）

1. 右上角切换到「演示用户 B」。
2. 持仓、委托、成交、资金流水都是独立账户的数据。
3. 切回「演示用户」，数据恢复。

讲解点：
- 同一套撮合引擎服务多个账户，账户间资金/持仓隔离。
- 做市商账户（`MM001`）与模拟交易员（`FLOW001`）不显示在默认视图，但它们的报价和成交在盘口/行情里。

## 场景 6：异常与风控（1 分钟）

| 操作 | 预期 |
|---|---|
| 买入价格填 `200.00` | 返回 `40007 价格超出涨跌停范围` |
| 卖出数量填 `999999` | 返回 `40008 数量不符合最小变动单位` 或 `40001 单笔最大数量` |
| 可用资金不足时大额买入 | 返回 `40003 可用资金不足` |
| 撤已成交的委托 | 返回 `40006 当前委托不可撤销` |

## 场景 7：重置演示（30 秒）

1. 点击右上角「重置演示数据」。
2. 确认后，委托/成交/持仓/流水清空，账户恢复初始资金和持仓。
3. 做市商在 3 秒内重新报价，模拟交易员继续成交，K 线重新累积。

## 场景 8：清算与银行（2 分钟）

1. 点击顶部「清算与银行」。
2. 顶部卡片显示：
   - 通道状态：清算所适配器 UP、模拟银行 UP（DEMO-CLEARING）；
   - 未清算成交 ≥ 1 笔、未清算金额随模拟成交变化；
   - 银行结算账户合计与内部资金合计（未清算手续费会造成差异）。
3. 点击「执行日终清算」→ 确认。
4. 观察：
   - 「清算批次」出现一条 `CL...`，状态 `COMPLETED`，清算所回执 `ACCEPTED`；
   - 「批次明细」上方显示回执号 `CH-CL...` 与「重新上报」按钮；
   - 「批次明细」按账户/商品展示期初、买入、卖出、期末、手续费、净额；
   - 「对账结果」显示清算前银行余额、结算金额、`SETTLED`；
   - 「银行流水」出现 `清算结算` 记录，外部流水号为 `CH-CL...`。
5. 在「银行结算账户」里对「演示用户」点「入金」，金额 500，确认。
6. 观察：银行余额 +500，内部资金余额同步 +500，银行流水出现「入金」，外部流水号为 `MB...`。
7. 点「出金」，金额 200，观察两个余额同步 −200。
8. 点击「交易终端」回到盘口。

讲解点：
- 清算按 `(账户, 商品)` 归集未清算成交，期初 = 期末 − 买入 + 卖出。
- 清算完成后通过 `clearing-adapter` 上报清算所，回执 `CH-<batchNo>`；重报使用同一幂等键，不会重复调账。
- 适配器通知 `mock-bank` 按账户调账，最后本地银行、内部资金、模拟银行三方一致。
- 入金/出金先经适配器调用模拟银行，成功后再落本地账；外部流水号写入银行流水。
- 这是演示级清算，不涉及真实银行通道、多边净额、日切/夜盘。

## 收尾话术

> 这个演示保留了原系统交易核心的撮合规则和表结构，去掉了配置中心、注册中心、消息队列，用 22 张表、4 个演示账户、三个 Java 服务和一个 Vue 终端还原了“下单 → 撮合 → 成交 → 持仓/资金 → K 线/深度行情 → 日终清算 → 适配器上报 → 模拟银行出入金/对账”的完整闭环。  
> 下一步可以把 `clearing-adapter` / `mock-bank` 替换为真实银行/清算所适配器。
