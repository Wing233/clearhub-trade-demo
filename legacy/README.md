# Legacy 归档说明

本目录**不包含**原始代码。原始代码仍保留在工作区的其他目录中，本项目只保留可运行子集。

## 原始代码概况

原始工作区包含多套同源系统：

- 一套银行/清算接入底座（清算中心 + 银行渠道 + 模拟适配器 + 管理端）；
- 一套交易平台（多模块、配置中心、注册中心）；
- 一套现货交易主系统（下单、撮合、成交、持仓、资金、清算）；
- 多个银行/清算所定制分支（同一产品族的复制/裁剪版本）；
- 一个与交易无关的个人任务调度 demo。

这些系统共享私有 Maven 制品与历史数据库结构。由于无法取得私有 jar 和 MySQL DDL，**不能原样构建/启动**；同时部分目录包含真实银行资料、内网地址和凭据，不适合放入公开仓库。

## 本项目与原代码的关系

- 复用：撮合规则（价格优先、时间优先、成交价取被动方）、核心表名与资金/持仓语义；
- 重写：下单入口、资金账本、持仓服务、查询 API、WebSocket、交易前端、建表脚本；
- 删除：银行协议、清算文件、客户数据、真实凭据、配置中心/注册中心/消息队列依赖。

详见 [../docs/COMPATIBILITY.md](../docs/COMPATIBILITY.md)。

## 归档规则

如果要把原始代码放入本仓库的 `legacy/`：

1. **只放源码**，排除：
   ```
   .svn/ .idea/ target/ node_modules/ venv/ cache/
   *.log hs_err_pid*.log
   *.jar（除非确认可公开）
   ```
2. **删除真实凭据与客户数据**：
   - 数据库/Redis/RabbitMQ/SFTP 密码；
   - 邮箱授权码、短信/钉钉/QQ Bot Key；
   - RSA/SM2 私钥、银行证书、VPN 配置；
   - 真实银行卡号、身份证号、手机号、客户 CSV/DB；
   - 内网 IP、SVN/Nexus 地址、域名。
3. **推荐放在私有分支或私有仓库**，不要推到公开远端。
4. 推送前运行：
   ```bash
   gitleaks detect --source . --verbose
   ```
5. 在归档目录放一份 `README.md`，说明来源、用途、不可运行原因。

## 为什么不在本仓库复制原始代码

- 体量大（约 9,000 个 Java 文件 + 大量前端/配置/二进制）；
- 含真实凭据、银行资料、客户数据，公开风险高；
- 对演示没有增量价值，反而增加构建噪音与误用风险。

本项目的目标是“可运行、可演示、可部署”，不是“原样备份”。
